# Phase 2: Ultra FP4 Quantization - Context

**Gathered:** 2026-05-27
**Status:** Ready for planning

<domain>
## Phase Boundary

This phase delivers Ultra FP4 dequantization as a new Vulkan shader operation — a GLSL compute shader converts 4-bit floating point (E2M1) weights to FP16 (or FP32) at runtime on GPU. The op is integrated as a dequant variant in the Vulkan backend, embedded via `makeshader.py`, and tested against a CPU reference with acceptable precision. Covers requirements FP4-01 through FP4-06.
</domain>

<decisions>
## Implementation Decisions

### FP4 Format Encoding
- **D-01:** E2M1 encoding — 1 sign bit, 2 exponent bits, 1 mantissa bit. This is the standard 4-bit floating point format.

### Op Integration Pattern
- **D-02:** Implemented as an existing dequant variant within the Vulkan backend. Not a new standalone OpType — integrate into the existing dequantization flow to reuse the loaded shader infrastructure.

### Weight Packing
- **D-03:** 2 FP4 values packed per byte. Packing optimized for GLSL storage buffer reads with swizzling as needed for GPU memory access patterns.

### Dequantization Target Precision
- **D-04:** Default target is FP16 (half precision) for GPU memory bandwidth efficiency. FP32 output supported via a flag for higher precision when needed.

### Carried Forward from Phase 1
- **D-05:** Vulkan buffer backend only (not image backend).
- **D-06:** Correctness testing takes priority over performance optimization.
- **D-07:** Tests registered under `op/vulkan/` prefix, log warning on Vulkan skip, fixed seed default.
- **D-08:** Shader autogeneration via `makeshader.py` → `AllShader.cpp`/`.h`/`VulkanShaderMap.cpp`.
- **D-09:** Build configuration: `MNN_USE_SYSTEM_LIB=ON` with MoltenVK static linking + Apple Metal frameworks.

### the agent's Discretion
None — all gray areas were decided by the user.

- **`makeshader.py` pipeline:** Proven pattern from Phase 1 (`attention_mask_gen.comp` → AllShader → VulkanShaderMap). New `fp4_dequant.comp` follows the same path.
- **`VulkanBackend::addCreator` pattern:** `source/backend/vulkan/buffer/backend/VulkanBackend.cpp:553` — registration point for new ops. Study existing dequant/conversion creators.
- **INT4/INT8 weight prepare shaders:** `conv1x1_int4_weight_prepare.comp` — packing pattern. The FP4 dequant shader is the inverse operation (unpack → convert to float).

- **makeshader.py:** Reads `glsl/` directory, regenerates autogenerated files
- **Model loading:** The `.mnn` model format must carry FP4 weight packing metadata (2-per-byte, swizzle pattern) for the shader to correctly unpack
- **Downstream ops:** FP4 dequant output (FP16/FP32) feeds into standard matmul/attention ops — must match expected input precision

<specifics>
## Specific Ideas

- E2M1 encoding: sign=1, exponent=2, mantissa=1. Dequantization formula: `(-1)^s × 2^(e-bias) × (1 + m/2)` where bias=1 for E2M1.
- Weight swizzling for GPU memory coalescing — packed byte layout should favor contiguous reads in the shader's workgroup dispatch pattern.
- FP16 default, FP32 flag — the flag could be a GLSL preprocessor define (`#define FP4_OUTPUT_FP32`) or a runtime uniform.
</specifics>
