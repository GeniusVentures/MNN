<objective>
Build the standalone `sgfp4_inject` tool: given a normally-converted `.mnn` plus one or more gnus-poc `fp4_exporter.py --adaptive` output directories, produce a new `.mnn` + merged external sidecar where each target weight tensor is produced by an `OpType_SGFP4Dequant` node — correct at the Express/`Module::load` level.

Purpose: This is the first producer of a real, loadable `.mnn` that actually uses `OpType_SGFP4Dequant` on real weights. Every difficult sub-problem (decode, serialization, shape inference, op registration) is already solved in-repo; this plan wires them together using the recipe proven by Plan 05-01.

Output: `tools/fp4/sgfp4_inject.cpp` (single-TU tool), `tools/fp4/sha256.hpp` (vendored SHA-256), `tools/fp4/CMakeLists.txt`, and the root `CMakeLists.txt` option/include wiring. Builds `sgfp4_inject.out` behind `MNN_BUILD_SGFP4_TOOLS`.
</objective>

| T-05-02 | Tampering | container integrity | mitigate | `sgfp4::sha256_hex(container)` compared to manifest `fp4_binary.sha256`; mismatch → hard error (D-03) |
| T-05-03 | Spoofing | manifest path/JSON | mitigate | Never resolve `fp4_binary.path` literally (root-relative, backslash-separated); discover unique `*.sgfp4` in `--niche-dir`, cross-check basename only; validate `stats.shape` is 2 positive ints |
| T-05-04 | DoS | oversized container allocation | mitigate | Bounds-checked `dequant_sgfp4_container_cpu` (ASVS V5); `CPUSGFP4Dequant::onResize` bounds `external()[1]` against real file size before resize |
| T-05-05 | Logic | ambiguous shape match | mitigate | Exact-shape match only; zero-or-multiple matches → hard error listing candidates (D-02); no transpose fallback (D-04) |
| T-05-06 | Integrity | corrupt artifact emitted | mitigate | Unconditional in-tool reload + oracle comparison after save; mismatch → nonzero exit (D-12/D-13) |
| T-05-SC | Tampering | package installs | accept | No npm/pip/cargo installs; vendored `sha256.hpp` is a single reviewed source file, not a registry dependency |
