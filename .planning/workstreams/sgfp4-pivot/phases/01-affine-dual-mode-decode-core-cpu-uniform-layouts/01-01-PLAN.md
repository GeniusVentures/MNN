<objective>
Add a new dedicated CPU decode op for the SGFP4 v2 container restricted to uniform layouts. This delivers the affine dual-mode reconstruction math (`w = S*c + bias`), FP16 parameter unpack, v2 self-framed stream parsing, the uniform-layout record walk, and the external-sidecar container plumbing — all on CPU, with no quadtree complexity (LAYOUT_MIXED is Phase 2).

This is effectively an MNN "add-new-op" following `skills/add-new-op/SKILL.md` steps 1->3 (schema -> shape -> CPU backend). It is purely additive: it introduces `OpType_SGFP4Dequant`, a new `SGFP4DequantParam` descriptor, a new header-only decode library, a new CPU `Execution`, and a new shape computer. It does NOT touch the existing E2M1 path (`include/MNN/FP4DequantUtils.hpp`, `source/backend/cpu/CPUFP4Dequant.*`) or the live `dequant_fp4_packed_cpu` cross-repo contract (Success Criterion 5 / ROADMAP additive-not-replacement lock).

Purpose: Prove decode correctness for both code modes and establish the container-loading plumbing so the encoder + round-trip tests (Plan 01-02) and the later Vulkan port (Phase 3) build on a CPU-validated reference.

Output: schema edits + regenerated `MNN_generated.h`; `ShapeSGFP4Dequant.cpp`; `include/MNN/SGFP4DequantUtils.hpp`; `CPUSGFP4Dequant.{hpp,cpp}`; regenerated register lists. Covers SGV2-01, SGV2-02, SGV2-03, SGV2-04, SGV2-05, SGV2-06. Behavioral round-trip verification is delivered by Plan 01-02's `test/op/SGFP4DequantTest.cpp` (the Wave-0 test scaffold).
</objective>
