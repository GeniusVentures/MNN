       SGFP4: Adaptive Dual-Mode Macroblock Quantization
  with GPU-Friendly Unpacking and Verifiable Decode Semantics

                                                  Kenneth Hurley
                                            GNUS.AI / Super Genius

                                                                  Abstract

             We present Super Genius FP4 (SGFP4), a GPU-oriented weight-compression container for neural-
        network inference built from three ingredients: (i) an affine integer reconstruction rule shared by two
        per-block code modes, a 4-bit signed mode (FP4 AFFINE) and a ternary mode in the 1.58-bit class
        (T158 AFFINE); (ii) flag embedding in structurally free low-order bits, which removes separate metadata
        fetches from the decode path; and (iii) two container profiles that share the same modes and packing
        rules. The v1 fixed-payload profile stores every 64×64 macroblock as a compact header plus a constant
        2048-byte payload, giving uniform addressing, trivial prefetching, and stable kernel structure. The v2
        quadtree-adaptive profile subdivides difficult macroblocks into per-region blocks with their own affine
        parameters and code modes, trading addressing uniformity for accuracy at a measured density cost. We
        give a complete normative specification, including byte order and intra-word code ordering, so that
        independent implementations decode bit-identically; we analyze subdivision under a fixed payload budget
        and show that explicit per-tile headers make uniform 4-bit subdivision infeasible at every granularity
        below the macroblock, motivating the variable-size v2 profile; and we describe how the integer-dominant
        ternary path supplies reference decode semantics for execution attestation in decentralized inference. An
        exemplary GPU unpack kernel and a full evaluation protocol are provided; empirical results are left to a
        companion report.

1 Introduction

Modern inference workloads are frequently memory-bandwidth bound: weight tensors are large, reused
imperfectly due to cache limits, and accessed with patterns that benefit from regularity and alignment. Low-bit
quantization reduces bandwidth but typically introduces either (a) irregular, variable-length layouts that are
difficult to decode efficiently on GPUs, or (b) simple fixed layouts that sacrifice accuracy when a single
quantization mode is applied uniformly.

     SGFP4 targets the intersection of compression, GPU efficiency, and -- unusually for a quantization format
-- verifiability. The format was developed for the GNUS.ai distributed inference network [7], where untrusted
nodes execute declared models and must be spot-checked cheaply. This deployment adds a requirement
that mainstream formats do not address: two honest implementations on different hardware must be able
to decode the same container to bit-identical weights, so that execution claims can be verified by replay.
That requirement shapes several design choices, most importantly the use of affine integer codes rather than
floating-point codebooks, and a normative specification of byte order and intra-word code ordering.

     The contributions of this paper are:

    1. A dual-mode affine container in which each macroblock (or sub-block) selects between a 4-bit signed
        integer mode and a ternary mode under a single reconstruction rule w^ = S · c + , with parameters
        stored as a packed FP16 pair (Section 3).

                                                                1
   2. The v1 fixed-payload profile: constant 2048-byte payloads per 64×64 macroblock with mode flags
       embedded in the low bits of 16-byte-aligned offsets, giving uniform addressing and zero-cost metadata
       (Section 4).

   3. A feasibility analysis of subdivision within a fixed payload, showing that explicit per-tile headers
       force mode mixing at every sub-macroblock granularity and identifying an interesting extreme point --
       all-ternary 4×4 tiles at the same 4.0 bits/weight external density as plain FP4 (Section 5).

   4. The v2 quadtree-adaptive profile: variable-size macroblock records whose leaves are chosen by an error-
       driven quadtree with per-level thresholds, per-region mode selection, and optional Laplacian-pyramid
       error weighting (Section 6).

   5. A verifiable-execution codesign: reference integer decode semantics, with the ternary path enabling
       bit-exact cross-device attestation at the cheapest verification class in the GNUS Execution Integrity
       System (Section 8).

2 Related Work

Encoders are orthogonal to this work. SGFP4 is a container and decode specification. Code assignment
inside a block may be produced by round-to-nearest (as in our exemplary encoder), or by error-compensating
methods such as GPTQ [4] or activation-aware scaling such as AWQ [9]; any encoder that emits valid
codes and parameters produces a conforming container. Outlier-aware schemes [1, 8] similarly motivate our
per-region mode selection and the ternary outlier veto in the v2 encoder, but operate at the encoding layer.

Block formats. QLoRA's NF4 [2] uses a 16-entry non-uniform codebook per small block; decoding is a
table lookup. SGFP4 deliberately uses affine integer codes instead: reconstruction is a fused multiply­add on
a sign-extended nibble, which vectorizes well and, unlike a floating-point codebook, admits integer-exact
reference semantics for verification (Section 8). GGUF k-quants in llama.cpp [6] are the closest prior
container design: 256-weight super-blocks contain sub-blocks with their own (quantized) scales and minima.
SGFP4 differs in four ways: (1) the v1 profile keeps a constant external payload regardless of the encoder's
internal choices, so addressing is uniform across an entire tensor; (2) the two code modes may be mixed
per block within one tensor, selected by measured error rather than fixed per file; (3) the v2 profile adapts
granularity by an error-driven quadtree rather than a fixed sub-block grid; and (4) metadata rides in structurally
free low-order bits of aligned offsets or of the packed parameter word, rather than in separate scale streams.
OCP Microscaling (MX) formats [12, 11] attach a shared 8-bit exponent to fine-grained groups of 32 elements;
SGFP4 instead uses a full FP16 scale and bias at coarser granularity, with subdivision available where finer
parameters pay for themselves. BitNet b1.58 [10] demonstrates ternary training; SGFP4's T158 AFFINE is
a post-training storage and decode mode that any sufficiently flat block may adopt, with an affine correction
per region.

Kernels and extreme compression. Marlin [5] shows that carefully structured 4-bit layouts sustain near-
ideal speedups on modern GPUs; SGFP4's fixed payloads and shift­mask decode are designed to be similarly
kernel-friendly, including on mobile-class Vulkan devices. Vector and lattice quantizers such as AQLM [3]
and QuIP# [13] reach lower bit-rates at the cost of heavier decode (codebook gathers, Hadamard transforms);
SGFP4 occupies the opposite point -- decode is a handful of shifts, masks, and one FMA per weight.

Verifiable inference. Zero-knowledge proofs of inference remain orders of magnitude too expensive for
interactive serving. The GNUS Execution Integrity System [7] instead verifies execution honesty by teacher-

Novelty and positioning. It is worth being precise about which parts of SGFP4 are new. Per-block affine
scale-and-bias quantization (Eq. (2)) is standard practice, shared with GPTQ, AWQ, NF4, and GGUF's
k-quants [4, 9, 2, 6]; a reader familiar with those formats should not expect the numerics alone to be a
contribution. Two elements are new in this literature but have direct precedent elsewhere: error-driven spatial
quadtree subdivision (Section 6) is, to our knowledge, unused in weight quantization, but is exactly the
block-partitioning strategy long used in image and video codecs (JPEG2000, HEVC/AV1) to spend bits where
a local region is hard to approximate and stay coarse where it is not; we import that mechanism rather than
invent it, and Section 9 calls out the open empirical question it raises. The v1 invariant that every macroblock
occupies an identical 2048-byte payload regardless of which mode the encoder chose internally -- letting
FP4 and ternary blocks mix freely within one tensor while addressing stays uniform -- is, to our knowledge,
a modest but genuine container-level contribution: existing formats fix one quantization type per tensor or per
file, or vary sub-block size without a constant external stride. The element with no precedent we are aware of
in any quantization format, mainstream or otherwise, is the one argued in Section 8: a decode specification
closed enough -- byte order, intra-word bit order, rounding, and reserved-bit behavior all normative -- that
independent, mutually untrusting implementations on different hardware must reach a bit-identical tensor,
making the container usable as a trust primitive rather than only a compression scheme. That requirement did
not originate in the quantization literature; it was imposed by the verification problem of Section 8 and is, in
our view, the paper's central claim.

3.1 Notation and tiling

We describe a container representing a weight matrix W of shape [O, I] (output channels by input channels).
The tensor is padded, conceptually or physically, with zeros to multiples of 64 in both dimensions. The 64×64
external addressing unit is called a macroblock (parts of the reference implementation use the synonym
superblock). Define

Ty = O/64, Tx = I/64, B = Ty · Tx.                (1)

Macroblock index b  [0, B) maps to grid coordinates (by, bx) by by = b/Tx and bx = b mod Tx, in
row-major order.

3.3 Two container profiles

SGFP4 defines two profiles that share modes, parameters, and packing rules (Table 1). Profile v1 (Section 4)
optimizes for uniform addressing: every macroblock contributes exactly 4 + 4 + 2048 bytes -- one header
word, one offset word, and one payload -- amortized across the three parallel arrays of Section 4, not
as a contiguous per-macroblock record. Profile v2 (Section 6) optimizes accuracy per bit on difficult
tensors: macroblock records are variable-size and internally subdivided. Section 5 explains, quantitatively,
why subdivision and a fixed payload do not combine under explicit per-tile headers, which is why v2 is
variable-size.

5 Subdivision Under a Fixed Payload: Feasibility Analysis

A natural extension of v1 is to keep the constant 2048-byte payload but let the encoder subdivide a macroblock
internally into uniform tiles, each with its own explicit FP16 (S, ) header (4 bytes) stored inside the payload.
Table 2 works out the budget.

    Two conclusions follow. First, with explicit per-tile headers, uniform all-FP4 subdivision is infeasible at
every level below L0: any fixed-payload subdivision scheme must mix modes or share parameters across tiles.
Second, L4 is an interesting design point in its own right: 2-bit ternary codes plus 2 bits/weight of amortized
affine parameters equal 4.0 bits/weight external density -- the same as plain FP4 -- but with 4×4-granular
scale and bias, a very different error profile that should win on outlier-dominated blocks. We retain this
analysis as motivation: the production adaptive profile (v2, next) instead relaxes the fixed payload and lets
record size follow the layout.

6 Profile v2: Quadtree-Adaptive Container

6.1 File framing

A v2 stream frames its own record structure:

Field                  Type      Size         Value / meaning

magic                  bytes     4            'SGF4'
version                uint8     1            0x02
B                      uint32    4            number of macroblock records
pad0                   bytes     7            zero padding to a 16-byte boundary
record offsets[B]      uint32[]  4B           byte offset of each record, relative to record region
pad1                   bytes     0­12         zero padding so the record region begins 16-byte aligned
records                --        var.         B macroblock records, in row-major macroblock order

The padded file header and the padded offset table place the record region at align16(16 + 4B); each record
then begins at a 16-byte-aligned offset within the region and is zero-padded to a 16-byte multiple, so intra-
record alignment guarantees hold in absolute file addresses for every B, not only B  0 (mod 4). (Without
pad1, records would be misaligned whenever B  0 (mod 4).)

     The stream is self-describing with respect to record structure only. The original tensor dimensions (O, I)
-- and therefore the macroblock grid (Ty, Tx) of Section 3.1 and the edge-padding crop -- are carried by the
enclosing model manifest, exactly as for v1 (Section 4): B alone cannot distinguish, for example, a 1×2
from a 2×1 macroblock grid. A fully standalone v2 stream would require (O, I) fields in its header; the
shipped profile deliberately keeps tensor geometry in the manifest so that both profiles share a single source
of truth for it.

Block order and the split map. For uniform layouts, leaves are stored in row-major raster order of the
tile grid, and no split map is present. For LAYOUT MIXED, the quadtree structure is serialized as a split
bitmap: visiting nodes in pre-order depth-first traversal with quadrant order top-left, top-right, bottom-left,
bottom-right, one bit per node of size  8 records whether that node is split (1) or is a leaf (0). Nodes of size
4 cannot split and contribute no bit. At most 1 + 4 + 16 + 64 = 85 bits are required; the map is stored in three
little-endian uint32 words (bit k of the map is bit k mod 32 of word k/32), upper bits zero. Leaves --
and therefore block headers and payloads -- are stored in the order the traversal encounters them.

Per-leaf headers with embedded flags. Each leaf header packs (S, ) exactly as in v1, then replaces the
low 4 bits of the word -- which are the 4 least-significant mantissa bits of  -- with flags: bit 0 = mode, bit 1
reserved (logarithmic-mode extension), bits 2­3 reserved (0). Note that ERROR HINT is a v1 offset flag only
(Section 4.2); it has no v2 counterpart, and v2 bit 1 must be written zero until the logarithmic-mode extension
is specified. The decoder recovers

S = half(h  16),  = half(h & 0xFFF0), flags = h & 0xF.                 (6)

Truncating 4 of the 10 FP16 mantissa bits bounds the relative bias error by 2-7  0.8% of || for normal
values; since  is a per-leaf mean-level correction, this is negligible against 4-bit and ternary code error, and
it buys inline flags without any separate metadata stream.

Per-leaf payloads. A leaf of edge size n stores n2 codes with the same normative packing as Section 4.3
(n2/8 words for mode 0, n2/16 words for mode 1, weight order row-major within the leaf), padded to a

16-byte multiple.

7 GPU Decoding

The format is designed for high-throughput decoding with predictable memory access: fixed (v1) or per-
record-aligned (v2) payloads enable vectorized loads; flags ride in words the decoder fetches anyway; and
per-weight work is a shift, a mask, a sign-extend or symbol map, and one FMA. A natural mapping assigns
one workgroup per macroblock, decoding into shared memory for a fused dequantize­matmul, or to a padded
output tensor for a standalone unpack pass.

8 Verifiable Execution and Determinism

SGFP4 is the weight substrate of a decentralized inference network in which nodes accept execution contracts
pinning model, container, kernel manifest, and sampling, and are verified by sampled teacher-forced replay
against checkpoint tolerance bands [7]. Two properties of the format matter there.

    First, the specification is closed: byte order, code ordering, the two's-complement and symbol mappings,
FP16 parameter encoding, the  flag-truncation rule, and reserved-bit behavior are all normative. A container
therefore determines its decoded tensor exactly, and independent implementations can be validated against
shared conformance vectors -- golden containers with known bit-exact decodes -- before being admitted as
verifiers.

    Second, the ternary mode is integer-dominant: codes are in {-1, 0, +1}, so the matmul inner product
over codes can be computed exactly in integer arithmetic and scaled once per (sub-)block by S with a 
correction term. Kernels built this way can register in the cheapest determinism class of the Execution Integrity
System (bit-exact reference semantics), where verification is an output-hash comparison and spot-check
redundancy is minimal; FP4-affine paths with floating-point accumulation register in a bounded-drift class
with checkpoint-band comparison. The economic consequence is a gradient toward deterministic kernels: the
more reproducible the decode-and-compute path, the cheaper the node is to verify and the better its effective
margin. To our knowledge no mainstream quantization format is specified tightly enough to support this
replay-based attestation across heterogeneous, mutually untrusting implementations; SGFP4 was designed to
be.

       norm, calibration activation magnitude); a channel- or magnitude-guided permutation prior to tiling is
       a natural fallback if spatial locality proves weak.

10 Design Variants and Extensions

The design admits variants while preserving its GPU-friendly properties. Macroblock geometry: 64×64
(4096 weights) is a convenient default; 128×32, 32×64, or 128×64 tiles may better match particular tensor
shapes and coalescing constraints. Payload size and alignment: other fixed sizes (1024 or 4096 bytes) and
stronger alignments (32 bytes, freeing 5 flag bits) are possible; all alignment-derived flag capacity follows the
same rule -- 2k-byte alignment frees k low bits. Flag placement: low bits of aligned offsets (v1), low bits of
the packed parameter word (v2), a parallel flags array, or a small header region are interchangeable carriers;
the two shipped profiles demonstrate the first two. Additional code modes: the mode space extends to 3-,
5-, or mixed-bit codes, per-channel variants, or small vector codebooks [3, 13], provided decode remains
shift­mask­FMA class and, where verification matters, integer-exact reference semantics are specified.
Shared parameters: subdivided layouts may derive per-tile parameters from shared values (e.g. shared 
with per-tile scale deltas) to revisit fixed-payload subdivision under the budget of Table 2.

11 Conclusion

SGFP4 combines an affine dual-mode code system with two container profiles: fixed 2048-byte macroblock
payloads for uniform addressing and maximal decode regularity, and a quadtree-adaptive profile that spends
bits where an error-driven encoder finds them necessary. The specification is deliberately closed -- endianness,
code order, parameter encoding, and reserved behavior are normative -- because the format is asked to
do something unusual for a quantization container: serve as the reproducible substrate for verifying that
untrusted machines ran the model they claimed. Fixed layouts make GPUs fast; closed semantics make
strangers checkable.
