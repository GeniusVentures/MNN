    CLI: `sgfp4_encode_dump.out --weights <f32-dump-path> --dimO <N> --dimI <M> --out <container-path>`

    Contract (exact):
    - Input file: raw little-endian FP32, exactly `dimO * dimI` values, row-major (the writer side — `validate_real_weights.py` in 10-03 — uses `numpy.ndarray.astype('<f4').tofile()`).
    - Read the file as bytes; require exact size `dimO * dimI * sizeof(float)` (mismatch → MNN_ERROR + exit 1). `dimO`/`dimI` must be positive integers ≤ 65536 (else exit 1).
    - Call `sgfp4_encode::encode(weights.get(), dimO, dimI)`. Empty-vector return (NaN/Inf/bad-dims contract from `sgfp4_encode.hpp`) → MNN_ERROR naming the condition + **exit 2, no output file written**.
    - Success → write the byte vector to `--out` (binary), MNN_PRINT a one-line summary (dims + container size), exit 0. Write must be atomic-enough for tooling: write to the final path only after the full encode succeeds.
    - No model parsing, no decode, no other responsibilities — this is a dump→container transducer only.

    CMake (mirroring the verified `sgfp4_inject.out` pattern in `tools/fp4/CMakeLists.txt`): `add_executable(sgfp4_encode_dump.out ${CMAKE_CURRENT_LIST_DIR}/sgfp4_encode_dump.cpp)` then `list(APPEND MNN_SGFP4_TOOLS sgfp4_encode_dump.out)` BEFORE the foreach. Linking: the foreach already applies `${MNN_DEPS}` + MSVC `/WHOLEARCHIVE`; additionally `target_link_libraries(sgfp4_encode_dump.out sgfp4_encode)` so the harness exercises the shipped encoder lib (unlike `sgfp4_inject.out`, which deliberately does NOT link it — keep that comment's distinction intact). Update the header comment to note the Phase 10 parity role.

    Build (PowerShell, Phase 9 verified lines): configure with `MNN_BUILD_SGFP4_TOOLS=ON` (existing build dir / preset) then `cmake --build build --config Release --target sgfp4_encode_dump.out`. It must build clean alongside the untouched `sgfp4_inject.out` and `sgfp4_encode` targets.
