<objective>
Extend the existing Vulkan buffer-backend shader (`sgfp4_dequant.comp`) so `locateElement` decodes LAYOUT_MIXED (enum 4) records via a bounded, stateless, per-thread quadtree split-map walk, completing the shader's layout-enum coverage per CONTEXT.md D-01..D-06/D-09/D-10 — the GPU half of SGV2-15. This plan implements the thread-per-weight strategy (D-01); it deliberately does NOT dispatch one workgroup per macroblock — per D-02, that parenthetical in SGV2-15's text is descriptive, not normative, and the binding success criteria (correct split-map walk + CPU/Vulkan parity) are what this plan and Plan 04-02 verify. Regenerate and commit the embedded shader artifacts via the locked `makeshader.py` pipeline (CLAUDE.md contract, ROADMAP note 5).

Purpose: This is the hardest remaining piece of the SGFP4 v2 Vulkan port — translating the CPU's stack-based pre-order-DFS quadtree walk (`sgfp4_walk_quadtree`) into GLSL-legal, bounded, recursion-free code that reproduces its leaf-visitation order and per-leaf geometry bit-for-bit, without adding shared memory, inter-thread sync, or host-side aux data (D-10).
Output: An extended `sgfp4_dequant.comp` (new MIXED branch + helper + named constants) and three regenerated, committed shader-embedding artifacts.
</objective>

Both are fixed compile-time constants, satisfying "no dynamic stack, no unbounded loop" even though the bound is larger than 4 — a fixed, larger bound is not "unbounded."

    Add two more constants to the existing framing-constants block (near `kAlign16`): `kSplitMapBytes = 12u` (mirrors `kSGFP4SplitMapBytes`) and `kQuadTreeMinSplitSize = 8u` (mirrors `kSGFP4QuadTreeMinSplitSize` — nodes with edge &lt; 8u never read a split bit and are always leaves).

    Key simplification (verified against the CPU reference during planning): `dequant_sgfp4_container_cpu` never reads `QuadNode.x`/`.y`, only `.n` (`SGFP4DequantUtils.hpp:403,435`) — so the GLSL stack only needs to hold each pending node's edge size `n` (a plain `uint[kMaxQuadTreeStackDepth]`), never (x,y,n) triples. Since all 4 children pushed by a split share the same edge size and decode never distinguishes which quadrant is which, pushing 4 identical `n/2u` values and popping LIFO reproduces the CPU's TL,TR,BL,BR pre-order-DFS bit-consumption sequence exactly.

    Implement a new helper function (name and exact parameter decomposition are discretion; e.g. `bool locateMixedLeaf(uint recStart, uint local, out uint leafOrdinal, out uint leafN, out uint inLeaf, out uint blockHeadersStart, out uint payloadCursor)`) that, given a MIXED record's `recStart` and within-record flat index `local`:
    1. Compute `blockHeadersStart = recStart + 4u + kSplitMapBytes` (the split map sits at `recStart + 4u`, spanning `kSplitMapBytes` bytes, mirroring `SGFP4DequantUtils.hpp:394-408`).
    2. Initialize `uint stack[kMaxQuadTreeStackDepth]` with `stack[0] = 64u`, `top = 1u`; running state `bitCursor = 0u` (split-map bit position, mirrors `SGFP4SplitMapReader.bit`), `leafOrdinal = 0u`, `elemsConsumed = 0u`, `payloadCursorRel = 0u` (payload bytes consumed by leaves strictly before the target, relative to the record's payload region start), a `found` bool guard, and captured `targetLeafOrdinal`/`targetN`/`targetInLeaf`/`targetPayloadCursorRel`.
    3. Loop up to `kMaxQuadTreeNodeVisits` times (stop early once `top == 0u`): pop `n = stack[--top]`. If `n &gt;= kQuadTreeMinSplitSize`: read one split bit at `bitCursor` via `(read_u32_le(recStart + 4u + 4u * (bitCursor &gt;&gt; 5u)) &gt;&gt; (bitCursor &amp; 31u)) &amp; 1u` (mirrors `words[bit&gt;&gt;5] &gt;&gt; (bit&amp;31)` from `SGFP4DequantUtils.hpp:158` — the shift amount `bitCursor &amp; 31u` is always in [0,31], safe per the masked-shift pattern already used by `read_u32_le`), then `bitCursor += 1u`. If the bit is 1u (split): push 4 copies of `n / 2u` (`top += 4u`) and continue to the next loop iteration without treating this node as a leaf.
    4. Otherwise (split bit was 0u, or `n &lt; kQuadTreeMinSplitSize`, i.e. a forced 4x4 leaf): treat as a leaf of edge `n`. If `!found &amp;&amp; local &lt; elemsConsumed + n * n`: set `found = true`, `targetLeafOrdinal = leafOrdinal`, `targetN = n`, `targetInLeaf = local - elemsConsumed`, `targetPayloadCursorRel = payloadCursorRel`. Else if `!found` (this leaf precedes the target): read this leaf's header word directly via `read_u32_le(blockHeadersStart + 4u * leafOrdinal)` (block headers are ordinal-indexed and directly addressable — no walk needed for this read), extract `mode = header &amp; kLeafModeBit`, compute `elems = n * n`, `words = (mode == 0u) ? (elems / kNibblesPerWord) : (elems / kSymbolsPerWord)`, and accumulate `payloadCursorRel += (4u * words + kAlign16 - 1u) &amp; ~(kAlign16 - 1u)` (the identical 16-byte-align formula the uniform branch already uses at line 148). Unconditionally then: `elemsConsumed += n * n`, `leafOrdinal += 1u`.
    5. After the loop: `blockHeadersBytes = 4u * leafOrdinal` (now the TOTAL leaf count, since the walk visited every node), `payloadsStart = (blockHeadersStart + blockHeadersBytes + kAlign16 - 1u) &amp; ~(kAlign16 - 1u)` (identical align16 formula to the uniform branch's existing `payloadsStart` computation at line 132). Output `leafOrdinal = targetLeafOrdinal`, `leafN = targetN`, `inLeaf = targetInLeaf`, `payloadCursor = payloadsStart + targetPayloadCursorRel`.

Else: `base += recordElems` and fall through to the next record (identical pattern to every existing branch).
